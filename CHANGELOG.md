# Changelog

## 3.15.0 — 2026-10-20

### Per-core CPU & polish
- The Performance Bar gains a **Core** metric (hottest CPU core) with a full per-core breakdown in its tooltip — quickly see whether a game is single-core-bound.
- Help → About now shows **version + build + macOS**, plus **GitHub releases** and **Check for updates** buttons.
- Version 3.15.0 (build 26).

## 3.14.0 — 2026-10-20

### Overlay, macros & panel Hz
- The **Performance Bar** now draws **CPU and GPU history sparklines** (rolling 60-second traces).
- **Combo macros** are now **multi-slot**: add any number of hold + tap → key combos, each removable, all saved with the profile.
- **Panel Hz** now reads the *current* display mode refresh rate (drops below max during gameplay are reflected), still honestly labelled “not game FPS”.
- Declared localization metadata (`en`) in Info.plist.
- Version 3.14.0 (build 25).

## 3.13.0 — 2026-10-20

### Per-game settings profiles
- Game profiles now bundle **mapping** (profile + auto-enable + Steam-Input pause), **overlay mode / visibility**, and **keep-awake** in one place.
- When a saved app becomes the frontmost window, Mac Gaming Helper applies the entire profile automatically.
- Earlier per-app mapping entries are migrated into the new profiles on first launch.
- Revamped the Mapping → **Game profiles** editor: app picker, overlay/keep-awake/mapping toggles, and a saved list with status chips.
- Version 3.13.0 (build 24).

## 3.12.0 — 2026-10-20

### Feel & documentation
- New **Haptic & trigger intensity** slider (Settings and Controller page) scales rumble strength and DualSense adaptive-trigger resistance from 30–100%.
- Added a **3D-rendered app mockup** to the README, generated by `scripts/make-3d-render.swift` and regenerated on every build.
- Version 3.12.0 (build 23).

## 3.11.0 — 2026-10-20

### In-game controls & design polish
- **Global profile hotkeys**: ⌘⌥1 / ⌘⌥2 / ⌘⌥3 now switch Mapping profiles system-wide, so you can change presets mid-game.
- The **Performance Bar** gains a **Session time** metric (mm:ss, then h:mm:ss), toggleable in Settings.
- **Copy refresh**: UI wording is now consistently “DualSense / DualShock 4” (PlayStation) instead of the old DualShock 4–only phrasing.
- Version 3.11.0 (build 22).

## 3.10.0 — 2026-10-20

### Global hotkeys (work in-game)
- **⌥⌘M** (pause/resume Mapping) and **⌃⌥⌘P** (toggle the Gaming Overlay) are now **system-wide global hotkeys** via Carbon — they keep working while a game is frontmost, instead of only when Mac Gaming Helper is focused.
- The Go menu still lists the actions (shortcut shown in the label); the global keys take over the actual keypress so there is no double-trigger.
- Version 3.10.0 (build 21).

## 3.9.0 — 2026-10-20

### Game at full potential
- New **Power & performance** card in Settings: detects **Normal / Low Power / High Power** mode (read-only `pmset`) and the system **thermal** state.
- Warns when **Low Power Mode** is capping CPU/GPU, and when the Mac is thermally constrained; one-click **Open Energy settings**.
- The **Performance Bar** gains a **Thermal** metric (nominal / fair / serious / critical), toggleable in Settings → Overlay & performance.
- Self-test adds power-mode parsing and thermal-state checks.
- Version 3.9.0 (build 20).

## 3.8.0 — 2026-10-20

### Launcher, mapping & DualSense
- **Mapping profile import / export**: export the active profile to a JSON file and import it back (with unique-id collision handling and optional rename from the file name).
- **Heroic deep-launch**: Epic / GOG / Amazon games on the Play page now launch directly via `heroic://launch/…` (falls back to opening Heroic if the deep link is not handled).
- **Adaptive-trigger demos**: DualSense now offers **Weapon + feedback**, **Slope ramp** and **Vibration** trigger effects (each resets after 2.5 s).
- **Bluetooth battery fix**: wireless pads no longer show a false 0% or low-battery warning — macOS exposes an unknown battery state over Bluetooth, so the app now shows “Connected” and explains that no exact percentage is available.
- Self-test adds a profile JSON round-trip and a Heroic deep-link check.
- Version 3.8.0 (build 19).

## 3.7.0 — 2026-10-20

- Optional **auto-enable Mapping** when a saved app is frontmost (Accessibility must already be granted).
- New **Game profiles** card on the Mapping page: pick a running app and a profile, tap Remember, and manage saved pairs (remove anytime).
- Works for any regular app (Steam, Heroic, a game, etc.); Mac Gaming Helper itself is excluded.
- Version 3.7.0 (build 18).

## 3.6.0 — 2026-10-20

### Pad Check
- New **Pad Check** wizard on the Controller page. Press each control once and it checks off automatically: left/right stick, Cross/Circle/Square/Triangle, L1/R1, L2/R2, all four D-pad directions, L3/R3, touchpad, Options and Create/Share.
- **19 controls for PlayStation pads**, with face labels and the Create/Share/View name adapted to the connected pad.
- Sticky progress, a completion banner, **Reset check**, and **Copy report** (pad, transport, battery, player slot, pass/incomplete and missing controls).
- Auto-detects controller changes and disconnects; the Wizard starts fresh for a different pad.
- Self-test now verifies the checklist coverage and detection rules for sticks, face buttons, triggers, D-pad and touchpad.

### Wireless readiness
- New **Wireless readiness** panel reads macOS Bluetooth power and paired/connected PlayStation devices through IOBluetooth.
- It tells you whether a DualSense/DualShock 4 is paired, whether it is currently wireless, and when it is safe to unplug USB (“paired — unplug USB to switch”).
- Manual **Check** button plus Bluetooth Settings shortcut; refreshes when the pad’s transport changes.
- `--controller-test` now prints Bluetooth power, paired devices and connected devices.
- Version 3.6.0 (build 17).

### Diagnostics
- Controller dump now includes light-bar, haptics, adaptive-trigger and touchpad capability flags.
- Diagnostics export includes Bluetooth power, paired and connected device names.

## 3.5.1 — 2026-10-20

### Input latency & mapping
- **Button presses are event-driven.** GameController’s `valueChangedHandler` now rebuilds the snapshot the instant a button, stick or trigger changes, so very fast taps are no longer missed between 30 Hz polls.
- **Held sticks keep moving the mouse.** Mapping now runs its own 60 Hz tick while enabled; previously the mouse only moved when the snapshot changed, so holding a stick still stopped aim movement.
- **App Nap no longer throttles Mapping.** A user-initiated activity assertion is held only while Mapping is actually live, so background key/mouse output stays on time without preventing normal sleep.
- **Overlay timers stay at full rate** while the Compact HUD / Performance Bar is visible (FPS, ping and pad status no longer lag).
- **Adaptive-trigger demo is one click from the Controller header** (DualSense only), alongside Identify pad.
- `--controller-test --watch` now waits for Cross, Circle, L2 and the left stick, then reports each one — useful for verifying a newly paired pad.

### Housekeeping
- `doctor.sh` reads the controller diagnostic binary-safely under `pipefail`.
- Version 3.5.1 (build 16).

## 3.5.0 — 2026-10-20

### PlayStation controller support
- **DualSense (PS5) is a first-class pad.** The Controller page shows adaptive-trigger status, and a new **Weapon + feedback demo** applies real L2/R2 resistance for 2.5 seconds, then resets automatically.
- **Correct USB vs Bluetooth detection.** GameController’s `isAttachedToDevice` does not mean “wired” on macOS, so the app now asks IOKit for the Sony HID transport (cached for two seconds). A USB DualSense is now labelled **USB**, not Bluetooth.
- **Background input works in-game.** `GCController.shouldMonitorBackgroundEvents` is enabled so Mapping and the overlay keep receiving pad input when Mac Gaming Helper is not frontmost.
- **Multiple pads get distinct Player 1–4 slots**, preventing two identical controllers from sharing the same identity.
- The DualSense **Create** button is labelled correctly; mapping profiles that use Share/Create both work.
- **Identify pad** flashes the light bar and sends a short haptic pulse so you can tell which controller is selected.
- The live diagram now uses ✕ ○ □ △ symbols instead of ambiguous first letters.
- New **`--controller-test`** CLI mode prints kind, transport, battery, player slot, light/haptics/adaptive/motion support and live axes:
  `"/Applications/Mac Gaming Helper.app/Contents/MacOS/MacGamingHelper" --controller-test`
- Pairing / Setup now has a **DualSense (PS5) / DualShock 4 (PS4)** selector with the correct cable (USB-C vs Micro-USB), pairing chord (Create + PS vs Share + PS), reset steps, and a “quit Steam while pairing” note.
- Self-test now reports connected controllers, adaptive-trigger support and background-input state.

### Health check
- `scripts/doctor.sh` gains a Controllers section (uses `--controller-test`) so USB/Bluetooth, battery and capabilities are visible without opening the app.

## 3.4.3 — 2026-10-20

### Launchers & Steam
- Steam and Rosetta 2 are now part of the supported setup. `./scripts/install-gaming-launchers.sh --steam` installs Rosetta 2 first when needed, then the Steam cask.
- The Launchers page detects Steam without Rosetta 2 and explains exactly how to fix it (one-click copy of the `softwareupdate` command).
- Session Prep reports “Needs Rosetta 2” instead of a misleading “Ready”.
- Added `scripts/doctor.sh`: one read-only health check for the app, Heroic, Steam, Rosetta, libraries, signatures, quarantine and shortcuts.

### Installer cleanup
- `install.sh` no longer mirrors a second copy into `~/Applications` when `/Applications` succeeds. Stale duplicates are removed so LaunchServices cannot open an old build.
- `fix-gatekeeper.sh` opens the app by path (more reliable than `open -a` with a path).
- Self-test now verifies detected launchers are real bundles and reports Steam / Rosetta state.

### Mapping & UI fixes
- “Auto-pause Mapping when app is inactive” now defaults to **off**, so keyboard/mouse mapping keeps working in the game. Held keys are still released when you switch apps, preventing stuck inputs.
- “Keep in Dock” now actually switches to accessory mode when unchecked; the app refuses to hide both the Dock icon and the menu bar item.
- The Performance Bar no longer rebuilds its SwiftUI root every second; live views observe the metrics directly.
- Menu-bar title/tooltip/tint only update when their values change.
- Steam library discovery also reads `config/libraryfolders.vdf`.

## 3.4.2 — 2026-10-20

### Launcher fixes
- **Heroic install repair:** `scripts/install-heroic.sh` replaces the broken `brew install --formula heroic` path with the real Homebrew cask, plus an official-DMG fallback that verifies the download before copying.
- `scripts/install-gaming-launchers.sh` rewritten: installs/repairs Heroic, and only installs Steam or GeForce NOW when explicitly requested.
- Launcher detection now validates that a `.app` is a real bundle (Info.plist + executable). Failed downloads saved as `.app` are shown as **Needs reinstall** with a repair action instead of “Installed”.
- Added Heroic’s official bundle name `Heroic-Games-Launcher.app` and bundle-ID lookup, so Heroic is found even when renamed or outside `/Applications`.
- Heroic library scan now reads Heroic 2.x manifests (`store_cache/legendary_install_info.json`, `gog_install_info.json`, `nile_install_info.json`, `sideload_apps/library.json`) as well as legacy paths.
- Install and Session Prep surface Heroic state; Play page has an **Install Heroic** action when missing.
- `scripts/install.sh` validates the build, runs the self-test before installing, and verifies the installed bundle afterwards.

### Performance & project health
- Idle CPU dropped from ~30–40% to under 1%: the 30 Hz controller poller no longer republishes identical state (which forced constant SwiftUI relayout).
- Frontmost-app polling only publishes real changes.
- Moved unsafe, non-parsing “M5 Pro” scripts and status docs to `archive/m5pro-legacy/` with an explanation. They referenced invented tools/URLs and one deleted `Steam.app`.
- `scripts/ci-validate.sh` no longer requires bash 4 `mapfile` (macOS ships bash 3.2).
- `scripts/open-permissions.sh` uses current System Settings pane URLs with legacy fallbacks.
- Build target now follows the host architecture instead of always `arm64`.
